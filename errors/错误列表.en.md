# Error List v1.0 (depends on kernel v1.0)

> [中文版](错误列表.md)

> XiRang's error code list. Error codes are stable: new codes are only appended, never reordered or reused. Format `X<three digits>`, grouped by layer:
> - **Node layer**: `E` structure / `R` reference (reported by the validator)
> - **Template layer**: `V` version / `O` order (reserved, not yet defined)
> - **Implementation layer**: `F` file (reported by the reader) / `C` conversion (reported by format conversion) / `W` writer (active)
>
> **How to read a code**: the first letter says which layer reported it; the three digits after it are that layer's n-th error. When you see something like `E005` or `W003`, look it up by code below.

## Node layer (active)

9 codes: E001 / E002 / E003 / E005 / E006 / E008 / E009 / E011 / R001. Reported by the validator ([tools/validator.py](https://github.com/outnever/XiRang/blob/main/tools/validator.py)).

### E001 ID missing

- Problem: the node ID is nil (16 zero bytes). nil may only be used in "parent" to mean root; a node's own ID must not be nil, otherwise it has no identity and references can never reach it.
- Fix: issue a real UUID (v4). This is a write error; reject the write.
- Example: ID all zeros → E001; change to `uuid.uuid4()` → passes.

### E002 ID conflict

- Problem: two nodes have the same ID. The ID is the globally unique identity; a collision makes a reference point at the wrong node.
- Fix: keep one, re-issue a new ID to the other.
- Example: A and B both have ID `550e8400-…` → E002; give B a new ID → passes.

### E003 ID format invalid

- Problem: the ID is not a valid UUID (e.g. `"abc"` or `123`). A defensive check; normal UUID types never trigger it.
- Fix: change to a valid UUID.
- Example: ID `"abc"` → E003; change to `uuid.UUID(...)` → passes.

### E005 parent self-reference

- Problem: the node's parent is itself, hanging itself under itself.
- Fix: set parent to another node, or to nil (making it a root).
- Example: A's `parent = A` → E005; set parent to nil → passes.

### E006 parent cycle

- Problem: walking up "parent" returns to the start (e.g. A's parent is B and B's parent is A, or a longer loop). A cycle means the tree has no root and traversal loops forever.
- Fix: break any one parent edge in the cycle (set some node's parent to another node or nil).
- Example: A→B→A or A→B→C→A → E006; break one parent edge → passes.

### E008 type tag invalid

- Problem: the node value's type tag is not within 0-6 (empty / integer / float / boolean / text / reference / blob).
- Fix: change to one of 0-6; future types only add new tags, old tags are never reused.
- Example: tag `99` → E008; change to "text" → passes.

### E009 value content invalid

- Problem: the value content does not match its type tag (e.g. tag "integer" but content is text; "reference" is not a UUID; "boolean" is not true/false; "empty" is not None).
- Fix: change the content to match the type tag.
- Example: `(integer, "not an int")`, `(reference, "abc")` → E009; change to `(integer, 42)`, `(reference, UUID)` → passes.

### E011 parent dangling

- Problem: the "parent" field holds an ID that does not exist in the store.
- Fix: set parent to an existing node, or to nil.
- Example: A's `parent = some ID not in the store` → E011; set to nil → passes.

### R001 reference dangling

- Problem: a "reference" value points at an ID that does not exist in the store.
- Fix: change the reference to an existing node; if caused by deleting the target, cascade-clean the reference.
- Example: B's value is `(reference, some ID)` not in the store → R001; add the target node → passes.

## Implementation layer (active)

Reported by the reader ([tools/tree.py](https://github.com/outnever/XiRang/blob/main/tools/tree.py) `load`) and format conversion ([tools/convert.py](https://github.com/outnever/XiRang/blob/main/tools/convert.py) `from_*`); raises an exception whose message contains the code.

### F001 magic invalid

- Problem: the first 4 bytes of the file are not `XRNG`.
- Fix: confirm this is a XiRang `.xirang` file; otherwise use the correct file.
- Example: file starts with `XXXX` → F001.

### F002 format version unsupported

- Problem: the format version in byte 5 is not the currently supported version (1).
- Fix: use a parser that supports that version, or regenerate the file at the current version.
- Example: version byte `99` → F002.

### F003 header length invalid

- Problem: the header length field (bytes 6-9, big-endian) is negative, or exceeds the remaining file length.
- Fix: the file is corrupt; regenerate it.
- Example: header length claims 1 GB but the file is 100 bytes → F003.

### F004 file truncated

- Problem: the node stream ends in the middle of a node (not enough bytes to finish reading one node).
- Fix: the file is corrupt; regenerate or complete it.
- Example: file ends while reading byte 10 of a node ID → F004.

### F005 index magic invalid

- Problem: the first 5 bytes of a sidecar index file (`.xirang.idx`) are not `XRIDX`.
- Fix: delete the index file and regenerate it (it is an implementation-layer cache, always rebuildable).
- Example: index starts with `XXXXX` → F005.

### F006 index version unsupported

- Problem: the index version byte is not the currently supported version (1).
- Fix: delete the index file and regenerate it.
- Example: index version byte `99` → F006.

### F007 index corrupt / truncated

- Problem: a sidecar index entry block runs past the end, or there are not enough bytes to finish reading it.
- Fix: delete the index file and regenerate it.
- Example: the index claims more entries than remain in the file → F007.

### F008 index inconsistent with source

- Problem: the node decoded at the indexed offset has a different ID than requested (the source changed but the index was not refreshed).
- Fix: rebuild the index automatically; if it recurs, check whether the source file is corrupt.
- Example: the offset does not contain the target UUID → F008, rebuild and retry.

### F009 node name too long

- Problem: the node name exceeds the 255-byte limit (the name length field is a single byte).
- Fix: shorten or split the name and write again.
- Example: a 600-byte name → F009; shorten it → passes.

### F010 type tag invalid

- Problem: when decoding, a node value's type tag is not within 0-6 (empty/integer/float/boolean/text/reference/blob).
- Fix: the file is corrupt; repair the tag or regenerate.
- Example: type tag byte `99` → F010.

### F011 text invalid UTF-8

- Problem: when decoding, a node name or text value is not valid UTF-8.
- Fix: the file is corrupt; repair the bytes or regenerate.
- Example: a text value with an invalid byte sequence → F011.

### C001 type name invalid

- Problem: during format conversion, a node value's `type` is not one of the 7 (empty / integer / float / boolean / text / reference / blob).
- Fix: change to a valid type name.
- Example: `{"type": "string", ...}` in JSON → C001.

### C002 UUID invalid

- Problem: during format conversion, the node ID / parent / reference value is not a valid UUID string.
- Fix: change to a valid UUID (hex in 8-4-4-4-12 form).
- Example: `"id": "abc"` in JSON → C002.

### C003 blob encoding invalid

- Problem: during format conversion, an inline blob's `value` is not valid Base64.
- Fix: change to a valid Base64 string.
- Example: `{"type": "blob", "value": "***", "encoding": "base64"}` → C003.

### C004 external file missing

- Problem: during format conversion, the file a blob's `ref` points at does not exist (or `blob_dir` was not provided).
- Fix: supply the external file, or use inline Base64 instead.
- Example: `{"type": "blob", "ref": "blob_xxx.bin"}` but the file is absent → C004.

### C005 node field missing

- Problem: during format conversion, a node is missing one of `id` / `name` / `value` (`parent` may be omitted; omitted = root).
- Fix: add the missing field.
- Example: a JSON node missing `"value"` → C005.

### W001 shard manifest missing

- Problem: opening a shard collection finds no `manifest.xirang`, or the manifest lacks the `@protocol = "shard-v1"` marker.
- Fix: confirm the directory is a shard collection, or regenerate it with `xr collection split`.
- Example: no `manifest.xirang` in the directory → W001.

### W002 shard file missing

- Problem: a shard file listed in the manifest does not exist in the directory.
- Fix: restore the shard file, or remove its entry from the manifest.
- Example: the manifest lists `xxx.xirang` but the file is absent → W002.

### W003 shard duplicate

- Note: **reserved** (not raised by the current implementation; `xr collection list` shows duplicate shards).
- Problem: multiple shards declare the same shard-root UUID (or the manifest has a duplicate filename).
- Fix: keep one, remove/rename the duplicate shard, and update the manifest.
- Example: two shards share the same root UUID → W003.

### W004 overlay log corrupt

- Note: **reserved** (not raised by the current implementation; a corrupt append record surfaces as F004 from `Store::load`).
- Problem: a shard's overlay log (appended revision records) cannot be parsed or folded.
- Fix: check whether the shard file is truncated/corrupt, or trigger compaction to rebuild it.
- Example: appended node bytes are truncated → W004.

### W005 shard rule invalid

- Problem: the `--rule` predicate is not `root` / `name:<name>` / `depth:<k>` / `marker:<name>`.
- Fix: use a valid predicate.
- Example: `--rule foo` → W005.

### W006 catalog corrupt

- Problem: the local catalog file (`catalog.idx`) has a bad magic / version / structure.
- Fix: delete the catalog file and rebuild it with a scan (it is only a cache).
- Example: the catalog file is truncated → W006.

### W007 catalog conflict unresolved

- Note: **reserved** (not raised by the current implementation; the same id in several files is **not** a conflict — that is normal).
- Problem: the same id appears in several files and the node's own name/value disagrees, so a human has to decide.
- Fix: inspect the disagreeing ids with `xr catalog check` (each entry shows both sides' children as context), then align the other copies' name/value with `xr catalog check --sync <uuid> --base <file>` (children are left alone).
- Example: the same id has different names in two files → potential W007 (listed by `xr catalog check`).

### W008 catalog entry stale

- Note: **reserved** (not raised by the current implementation; stale entries are overwritten by `xr catalog scan` or dropped by `forget`).
- Problem: a file recorded in the catalog no longer exists, or its fingerprint no longer matches.
- Fix: drop the stale entry with `xr catalog forget <path>`, or re-run `xr catalog scan`.
- Example: the catalog lists a deleted file → W008.

## Template layer (reserved)

The `V` version / `O` order domains, corresponding to the Template layer (version chain, order, prefix); not yet defined.

## Usage conventions

- Node layer: the validator outputs `code + node ID + description`, e.g. `R001 <w-8f2c…> reference target missing`.
- Implementation layer: the reader / format conversion raises an exception whose message contains the code, e.g. `F001: magic invalid`, `C001: type name invalid`.
- External format syntax errors (e.g. JSON / XML / YAML parse failures) are reported by the respective parser; XiRang defines no error code for them.
- Error codes are only appended, never reordered / reused, so logs remain traceable long-term.
