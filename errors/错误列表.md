# 错误列表 v1.1（依赖内核 v1.0）

> 息壤的错误码清单。错误码稳定：新增只追加、不重排、不复用。格式 `X<三位>`，按层分域：
> - **节点层**：`E` 结构 / `R` 引用（校验器报）
> - **模板层**：`V` 版本 / `O` 顺序（预留，暂未定义）
> - **实现层**：`F` 文件（读取器报）/ `C` 转换（格式转换报）/ `W` 写入器（已生效）
>
> **怎么读**：编号的首字母表示「哪一层报出来的」，字母后的三位数字是这一层里的第几个错误。看到形如 `E005`、`W003` 的编号，在下面按编号查即可。

## 节点层（已生效）

共 9 个：E001 / E002 / E003 / E005 / E006 / E008 / E009 / E011 / R001。由校验器（[tools/validator.py](https://github.com/outnever/XiRang/blob/main/tools/validator.py)）报告。

### E001 编号缺失

- 问题：节点编号为 nil（16 字节全 0）。nil 只能用于「父节点」表示根；节点自身编号不能是 nil，否则它没有身份、引用也指不到它。
- 解决：发真实 UUID（v4）。属写入错误，拒绝写入。
- 例：编号全 0 → 报 E001；改 `uuid.uuid4()` 通过。

### E002 编号冲突

- 问题：同一个文件里出现两条相同编号的记录，且**没有被声明为修订**。编号是全库唯一身份，撞号会让「引用」指错人。
- 例外：根下挂 `@protocol = append-v1`（见 [协议](https://github.com/outnever/XiRang/blob/main/spec/协议.md)）时，同编号多记录 = 修订，读时取最后一条，**不算冲突、不报 E002**。
- 解决：保留一条，给另一条重新发号；或者（本意就是修订时）补上 `append-v1` 声明。
- 例：A、B 编号都是 `550e8400-…` → 报 E002；B 换新编号通过；若根下声明了 `append-v1`，则 B 视为 A 的修订、不报。

### E003 编号格式非法

- 问题：编号不是合法 UUID（如 `"abc"` 或 `123`）。防御性检查，正常用 UUID 类型不触发。
- 解决：改成合法 UUID。
- 例：编号 `"abc"` → 报 E003；改 `uuid.UUID(...)` 通过。

### E005 父节点自指

- 问题：父节点 = 节点自身，自己挂在自己下面。
- 解决：父节点改成别的节点，或改成 nil（让它成为根）。
- 例：A 的 `父节点 = A` → 报 E005；父节点改 nil 通过。

### E006 父节点成环

- 问题：沿「父节点」向上回到自己（如 A 的父是 B、B 的父是 A，或更长的一圈）。成环则树无根、遍历死循环。
- 解决：断开环中任意一条父边（把其中某个节点的父改成别的节点或 nil）。
- 例：A→B→A 或 A→B→C→A → 报 E006；断一条父边通过。

### E008 类型标记非法

- 问题：节点值的类型标记不在 0-6（空 / 整数 / 浮点 / 布尔 / 文本 / 引用 / 二进制块）内。
- 解决：改成 0-6 之一；将来要新类型只新增标记，旧标记永不复用。
- 例：标记 `99` → 报 E008；改「文本」通过。

### E009 值内容非法

- 问题：值内容与类型标记不符（如标记「整数」却存文本；「引用」不是 UUID；「布尔」不是真/假；「空」不是 None）。
- 解决：改成与类型标记一致的内容。
- 例：`(整数, "不是整数")`、`(引用, "abc")` → 报 E009；改 `(整数, 42)`、`(引用, UUID)` 通过。

### E011 父节点断裂

- 问题：「父节点」填的编号在库中不存在。
- 解决：父节点改成库中存在的节点，或改成 nil。
- 例：A 的 `父节点 = 某不在库里的编号` → 报 E011；改 nil 通过。

### R001 引用断裂

- 问题：「引用」指向的编号在库中不存在。
- 解决：把引用改成存在的节点；若是删除目标节点导致的，级联清理这条引用。
- 例：B 的值是 `(引用, 某编号)` 而该编号不在库 → 报 R001；补上目标节点通过。

## 实现层（已生效）

由读取器（[tools/tree.py](https://github.com/outnever/XiRang/blob/main/tools/tree.py) 的 `load`）和格式转换（[tools/convert.py](https://github.com/outnever/XiRang/blob/main/tools/convert.py) 的 `from_*`）报告，抛出异常、信息含码。

### F001 魔数非法

- 问题：文件最前 4 字节不是 `XRNG`。
- 解决：确认是息壤 `.xirang` 文件；不是则换正确文件。
- 例：文件开头 `XXXX` → 报 F001。

### F002 格式版本不支持

- 问题：文件第 5 字节的格式版本不是当前支持的版本（1）。
- 解决：用支持该版本的解析器，或重新生成当前版本的文件。
- 例：版本字节 `99` → 报 F002。

### F003 头长非法

- 问题：头长字段（第 6-9 字节，大端）为负，或超出文件剩余长度。
- 解决：文件损坏，重新生成。
- 例：头长声称 1 GB 但文件只有 100 字节 → 报 F003。

### F004 文件截断

- 问题：节点流在某个节点中间结束（字节不够读完一个节点）。
- 解决：文件损坏，重新生成或补全。
- 例：读到节点编号第 10 字节时文件结束 → 报 F004。

### F005 索引魔数非法

- 问题：sidecar 索引文件（`.xirang.idx`）最前 5 字节不是 `XRIDX`。
- 解决：删除索引文件，重新生成（实现层缓存，可随时重建）。
- 例：索引开头 `XXXXX` → 报 F005。

### F006 索引版本不支持

- 问题：sidecar 索引第 5 字节的版本不是当前支持的版本（1）。
- 解决：删除索引文件，重新生成。
- 例：索引版本字节 `99` → 报 F006。

### F007 索引损坏 / 截断

- 问题：sidecar 索引的条目块越界或字节不够读完。
- 解决：删除索引文件，重新生成。
- 例：索引声称的条目数超出文件剩余字节 → 报 F007。

### F008 索引与源文件不一致

- 问题：按索引偏移读出的节点编号与目标不符（源文件被改但索引未刷新）。
- 解决：自动重建索引；若反复出现则检查源文件是否损坏。
- 例：索引指向偏移处却不是目标 UUID → 报 F008，重建后重试。

### F009 节点名超长

- 问题：节点名超过 255 字节上限（名字长度字段只有 1 字节）。
- 解决：把名字改短（或拆分），再写入。
- 例：名字 600 字节 → 报 F009；改短后通过。

### F010 类型标记非法

- 问题：解码时节点值的类型标记不在 0-6（空/整数/浮点/布尔/文本/引用/二进制块）。
- 解决：文件损坏；修复标记或重新生成。
- 例：类型标记字节 `99` → 报 F010。

### F011 文本非法 UTF-8

- 问题：解码时节点名或文本值不是合法 UTF-8。
- 解决：文件损坏；修复字节或重新生成。
- 例：文本值含非法字节序列 → 报 F011。

### F012 尾部残片已忽略

- 问题：追加写（`append-v1`）写到一半中断，文件末尾留下半条记录；整份重写的写入中断也可能留下同样形状的尾巴。
- 解决：读取时**忽略尾部残片**并提示（不当作整份文件损坏）；写入前把残片截断到最后一个完整记录边界，再继续追加。
- 例：在文件末尾追加 11 字节的残缺记录 → 打开时提示 F012，文件被截回上一个完整记录，数据照常可读。

### C001 类型名非法

- 问题：格式转换时，节点值的 `type` 不是 7 种之一（empty / integer / float / boolean / text / reference / blob）。
- 解决：改成合法的类型名。
- 例：JSON 里 `{"type": "string", ...}` → 报 C001。

### C002 UUID 非法

- 问题：格式转换时，节点编号 / 父节点 / 引用值不是合法 UUID 字符串。
- 解决：改成合法 UUID（8-4-4-4-12 格式的十六进制）。
- 例：JSON 里 `"id": "abc"` → 报 C002。

### C003 二进制块编码非法

- 问题：格式转换时，内联二进制块的 `value` 不是合法 Base64。
- 解决：改成合法 Base64 字符串。
- 例：`{"type": "blob", "value": "***", "encoding": "base64"}` → 报 C003。

### C004 外置文件缺失

- 问题：格式转换时，二进制块的 `ref` 指向的文件不存在（或未提供 `blob_dir`）。
- 解决：补上外置文件，或改用内联 Base64。
- 例：`{"type": "blob", "ref": "blob_xxx.bin"}` 但目录里没有该文件 → 报 C004。

### C005 节点字段缺失

- 问题：格式转换时，节点缺 `id` / `name` / `value` 之一（`parent` 可缺，缺 = 根节点）。
- 解决：补上缺的字段。
- 例：JSON 节点缺 `"value"` → 报 C005。

### W001 分片清单缺失

- 问题：打开分片词库时找不到 `manifest.xirang`，或清单缺 `@protocol = "shard-v1"` 标记。
- 解决：确认目录是 shard 词库，或重新执行 `xr collection split` 生成清单。
- 例：目录里没有 `manifest.xirang` → 报 W001。

### W002 分片文件缺失

- 问题：清单里登记的分片文件在目录中不存在。
- 解决：补回该分片文件，或从清单中移除该条目。
- 例：清单登记 `xxx.xirang` 但目录缺该文件 → 报 W002。

### W003 分片重复

- 备注：**预留**（当前实现不主动抛出；重复分片由 `xr collection list` 显示）。
- 问题：多个分片声明了同一个分片根 UUID（或清单里文件名重复）。
- 解决：保留一个，删除 / 重命名重复分片，并更新清单。
- 例：两个分片根 UUID 相同 → 报 W003。

### W004 覆盖日志损坏

- 备注：**预留**（当前实现不主动抛出；追加记录损坏会由 `Store::load` 报 F004）。
- 问题：分片的覆盖日志（追加修订记录）无法解析或折叠失败。
- 解决：检查分片文件是否被截断 / 损坏，或触发合并重建。
- 例：追加的节点字节截断 → 报 W004。

### W005 分片根判定器非法

- 问题：`--rule` 的判定器不是 `root` / `name:<名>` / `depth:<k>` / `marker:<名>`。
- 解决：改成合法判定器。
- 例：`--rule foo` → 报 W005。

### W006 目录损坏

- 问题：本机全局目录文件（`catalog.idx`）魔数 / 版本 / 结构无法解析。
- 解决：删除该目录文件，重新扫描重建（它只是缓存）。
- 例：目录文件被截断 → 报 W006。

### W007 目录冲突未解决

- 备注：**预留**（当前实现不主动抛出；同一编号出现在多个文件**不算冲突**，这是正常现象）。
- 问题：同一个编号出现在多个文件、且节点自身（名字 / 值）对不上，需要人来裁决。
- 解决：`xr catalog check` 查看自身不一致的编号（附两边各自的孩子作判断依据），再 `xr catalog check --sync <编号> --base <文件>` 把别处该节点的名字 / 值对齐（孩子不动）。
- 例：同一编号在两个文件里名字不同 → 潜在 W007（由 `xr catalog check` 列出）。

### W008 目录条目失效

- 备注：**预留**（当前实现不主动抛出；失效条目由 `xr catalog scan` 覆盖或 `forget` 移除）。
- 问题：目录记录的文件路径已不存在，或其指纹与记录不符。
- 解决：`xr catalog forget <路径>` 移除失效条目，或重新 `xr catalog scan`。
- 例：目录里记着已删除的文件 → 报 W008。

## 模板层（预留）

`V` 版本 / `O` 顺序 域，对应模板层（版本链、顺序、前缀），暂未定义。

## 使用约定

- 节点层：校验器输出 `码 + 节点编号 + 描述`，如 `R001 <w-8f2c…> 引用目标不存在`。
- 实现层：读取器 / 格式转换抛出异常，信息含码，如 `F001：魔数非法`、`C001：类型名非法`。
- 外部格式语法错误（如 JSON / XML / YAML 解析失败）由对应解析器报告，不另设息壤错误码。
- 错误码只在新增时追加，永不重排 / 复用，保证日志可长期追溯。
