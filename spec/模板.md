# 模板

> **一句话**：模板 = 一棵「形状固定下来、可以反复套用」的树。内核只规定节点长什么样；怎么把节点组织成一棵树，由你按需要自己定。
> **给谁看**：想用息壤存成套数据的人。本文件是模板层的用法演示，不是强制规定。

息壤的内核只管「节点」——四属性 + 7 大类（见 [README](https://github.com/outnever/XiRang/blob/main/README.md)），这部分是硬约束，由校验器（[tools/validator.py](https://github.com/outnever/XiRang/blob/main/tools/validator.py)）强制检查。

每个节点都带一个「父节点」字段（16 字节 UUID，全 0 = 根）。靠这个字段，节点天然串成上下层级，也就是「树」。最简单的树只要两个节点：一个根、一个子。

```
父
└─ 子
```

「树」是内核给你的、唯一天然的组织方式，它本身没有固定形状——怎么排布由你决定。

实际用起来，很多数据是成套、重复出现的：一份词条、一条记录、一类配置。与其每次都重新搭一遍，不如把这类树的形状固定下来、反复套用。这种「形状固定、可反复套用的树」，就叫**模板**。

模板不做强制约束，你按自己的使用场景设计就好。本文件是模板层的官方演示用法，仅供参考。

## 字符图例

本文用字符画树，读法约定：

```
`→` = 引用边；`←` = 读作（左边字符右边的解释）

名字 = 值           ← 名字:节点名;值:节点值（可以是文本 / 整数 / 浮点 / 布尔）
└─ 子节点名字       ← └─:父子连接边;子节点名字:子节点的节点名（子节点缩进在父节点下）

名字                ← 名字:节点名;节点值为空（空，类型0）

（空节点）           ← 名字空 + 值空（编号保留）；「删」后的槽位

名字 → 目标          ← 名字:节点名;目标:引用所指向的节点名（实际存的是节点编号UUID）

@名字               ← @ 前缀:辅助节点约定（非强制格式）
```

省略节点编号：字符图是「结构示意」，节点编号（UUID）不画；构建真实节点时由实现方生成，引用指向的正是它。

## 一、怎么定义一种模板

「模板」是一种「树」的模板。

定义模板**没有固定格式**，这里只展示几种可能的做法。

**方式一：模板节点**

构建一个「模板」节点，把要定义的树作为它的子树：

```
模板                                    ← 根
└─ 树
    └─ 树的内部结构
```

这样，树的结构（有哪些字段、怎么分层）就展示出来了。

好处：便于把多个模板集中挂在一个「模板」节点下统一管理；
代价：多包一层（树的根节点父不再是全 0）。

**方式二：辅助节点声明**

不改树的结构，直接在树的根节点上挂一个辅助节点，声明这棵树是「模板」：

```
树                                      ← 根
├─ @protocol = "模板"                   ← 声明：这棵树是模板
└─ 树的内部结构
```

（`@protocol` 是内嵌结构声明，见下一节「二、辅助节点」。）

好处：不改树结构、更轻量（`@protocol` 默认不参与正文）；
代价：声明分散、不便集中检索。

以上方式都只是「可选」，不是规定。

如何定义模板都可以，真正需要考虑的只有两件事：**实现方能否正确解析**，以及**大模型能否准确理解**。

除此之外，没有硬约束。

## 二、辅助节点

辅助节点 = 节点名以 `@` 开头的节点，存放「不参与当前视图」的元信息（格式、单位、来源、说明等）。

这是一种**命名约定**，不是内核约束，`@` 后的名字用英文。

辅助节点默认不参与「当前视图」读取，只在全量导出 / 审计时保留；值可为任意大类，多数是文本。

⚠️ **辅助节点是注入高发区**：`@note`、`@source` 等常被写入诱导文字，读取时同样只读、不执行（见 [README 安全提醒](https://github.com/outnever/XiRang/blob/main/README.md)）。

常见约定：

| 节点名                      | 含义                       | 例子                                            |
| ------------------------ | ------------------------ | --------------------------------------------- |
| `@format`                | 声明某值的格式 / 单位             | `@format = "pdf"`、`"unix timestamp"`          |
| `@address`               | 外置内容的存放位置                | `@address = "file:///data/blob/a3f5…"`        |
| `@fingerprint`           | 内容 SHA-256 摘要（内容寻址 / 校验） | `@fingerprint = "a3f5…"`                      |
| `@history`               | 旧版本容器（改的旧值快照、删的节点）       | `@history` 下挂旧值快照                             |
| `@created` / `@replaced` | 增 / 改时间（含「置空删除」）         | `@created = "2026-08-22T06:30:00+00:00"`      |
| `@note`                  | 给读者 / 大模型的说明             | `@note = "for the reader"`                    |
| `@source`                | 出处归因（文件路径 / URL）         | `@source = "file:///data/raw/dlg42.txt"`      |
| `@protocol`              | 内嵌的结构 / 约束声明             | `@protocol = "fixed point: 2 decimal places"` |
| `@模板`                  | 标注模板 / 来源：值空=我是模板；值=引用→我来自该模板 | 模板根挂 `@模板`(空)；实例根挂 `@模板`(引用) |
| `@实例`                  | 标注实例：值空=我是实例（实例根）          | 实例根挂 `@实例`(空)                                  |

约束标注（示例）：

```
树
├─ 字段A
│   └─ @note = "必填"                 ← 约定必填的节点
└─ 字段B
    └─ @protocol = "值域 {类, 实例}"   ← 约定值域范围
```

改与删：

节点的值可原位修改。「改」= 旧值复制进本节点的 `@history`（快照 + `@replaced`），编号不变、引用自动跟随：

```
改之前                          改之后
光源 = "能发光的物体"            光源 = "新的定义"
                                └─ @history
                                    └─ 光源 = "能发光的物体"      ← 旧值快照
                                        └─ @replaced = "…"     ← 修改时间
```

「删」= 把节点除「编号」外的字段（名字 + 值）置空，旧值进 `@history`（快照 + `@replaced`）；节点留在原位、编号保留，所以是一个「空槽位」：

```
删之前                          删之后
灯                               灯
└─ 光源 = "能发光的物体"          └─ （空节点）            ← 名字/值置空，编号保留
                                    └─ @history
                                        └─ 光源 = "能发光的物体"   ← 旧值快照
                                            └─ @replaced = "…"    ← 置空（改）时间
```

### 模板库与实例（`@模板` 与 `@实例`，注释式）

模板和实例都靠**根上的标注**识别，**不靠容器**——所以实例子树可以自由挂在任意父节点下（如词性实例可挂在词条实例的某个节点下）：

- **模板定义** = 一棵树，根挂一个值=<空>的 `@模板`（"我是模板"）。其**普通子节点** = 模板结构。
- **实例** = 一棵树，根挂一个值=<空>的 `@实例`（"我是实例"）+ 一个值=<引用→模板根>的 `@模板`（"我来自这个模板"）。实例根可自由挂在任意父节点下。

```
词条（模板定义，自由根）
└─ @模板（空）                       ← 我是模板
└─ 词形 / 词频 / 词义 → …            ← 模板结构

词条（实例，可挂任意父下）
├─ @实例（空）                       ← 我是实例
├─ @模板 → 词条模板（引用）            ← 我来自这个模板
├─ 词形 = "火"
├─ 词频 = 7
└─ 词义 → …
   └─ 01
      └─ 词性（另一模板的实例，嵌套在 词义/01 下）
         ├─ @实例
         └─ @模板 → 词性模板
```

**两种根节点**

- **孤立 / 自由根**：无 `@模板` / `@实例` 标注——自由摆放，无规格约束。
- **实例根**：挂了 `@实例`——规格统一的树，靠 `@模板`(引用) 关联到模板（结构改了多少也认得）。

**编辑规则**：向上找**最近的一个「有标注的根」**——是 `@模板`(空) 根 → 受保护（模板定义）；是 `@实例` 根或其它 → 可编辑。**无例外、无容器**。

**从模板实例化 / 批量导入**：模板的**普通子节点** = 模板「形状」。用一条记录（如 JSON 对象）按**名字**给每个节点填值，即可实例化一棵树（实例根挂 `@实例` + `@模板`(引用)），可自由放在任意父节点下；缺失字段留空。批量 = 对每条记录各实例化一棵。

示例：记录 `{"词形":"火","词频":7,"词义":{"释义":"燃烧物","词性":"名词"}}` → 实例树 `词条`（`@实例` + `@模板→词条模板` + `词形=火`、`词频=7`、`词义→释义/词性`）。

## 三、基础结构表达

用节点表达常见的基础数据结构（仅示例）。

值得说明的是，其实节点所组成的任意复杂树都无需任何约定即可读取，并组织成有意义的结构。此节所做的基础结构表达通常只用于服务实现层使用。

### 数组（有序列表）

一个节点挂一串子节点，顺序 = **追加序**（append-only，天然有序，无需序号）。

```
例句                              ← 数组容器
├─ "床头柜上有一盏灯。"              ← 元素 1（无名节点）
├─ "路灯在傍晚自动亮起。"             ← 元素 2
└─ "台灯放在书桌上。"                ← 元素 3
```

### map（键值对）

一个节点挂若干子节点，**子节点的「节点名」= 键，「节点值」= 值**。每条是「有名 + 有值」的叶子节点。该树同父下节点名要唯一（否则两个键同名，后者覆盖前者）。

```
员工信息                              ← map 容器
├─ 名称 = "张三"                   ← 键「名称」，值「张三」（文本）
├─ 年龄 = 30                       ← 键「年龄」，值 30（整数）
└─ 活跃 = true                     ← 键「活跃」，值 true（布尔）
```

### 枚举（闭枚 / 开枚）

枚举用「枚举容器 + 值域子节点」表达：类型（闭 / 开）用 `@protocol` 声明，当前值用引用指向值域里的某个子节点。

**闭枚**（固定值域）：

```
词性                              ← 枚举容器
├─ @protocol = "闭枚"             ← 声明：封闭（值域固定，就下面这些）
├─ 名词                            ← 值域项
├─ 动词
├─ 形容词
……
```

**开枚**（可扩展值域）：

```
领域                              ← 枚举容器
├─ @protocol = "开枚"             ← 声明：开放（值域可继续加类别）
├─ 医学                            ← 类别
├─ 法律
└─ 日常
```

当前值 = 引用 → 值域里的某个子节点（如「词性 → 名词」）。

约束靠实现层：节点只记录「值域 + 类型 + 当前值」；「当前值必须 ∈ 值域」「闭枚值域不可改」这类约束，由校验器（实现层）检查，节点本身不强制。

### 时间

值 = 整数（Unix 秒时间戳，默认 UTC）或文本（ISO 字符串）；单位 / 格式用 `@format` 声明。

```
事件
├─ 发生时刻 = 1704067200
│   └─ @format = "unix timestamp"   ← 声明单位
└─ 持续时长 = 3600
    └─ @format = "seconds"
```

### 其他常见结构

**集合（set）**：容器 + `@protocol = "集合"` 声明，元素 = 子节点；「元素唯一、无序」由校验器保证（内核不强制节点名唯一）。

```
水果（集合）                        ← 集合容器
├─ @protocol = "集合"              ← 声明：集合（元素唯一、无序）
├─ 苹果                             ← 元素
├─ 香蕉
└─ 橙子
```

**元组（tuple）**：数组，位置固定。

```
坐标
├─ "3"                              ← 第 1 位
└─ "4"                              ← 第 2 位
```

**队列 / 栈**：数组 + `@protocol` 声明端（先进先出 / 后进先出）。

```
队列
├─ @protocol = "队列"              ← 声明：先进先出
├─ "任务1"
├─ "任务2"
└─ "任务3"
```

**定点数**：整数 + `@protocol` 声明小数位。

```
价格 = 12345
└─ @protocol = "fixed point: 2"     ← 2 位小数 → 123.45
```

**复数**：实部 / 虚部两个子节点。

```
复数
├─ 实部 = 3.0
└─ 虚部 = 4.0
```

**记录（struct）**：map（字段名 = 子节点名）+ `@protocol` 声明「记录」（字段名唯一，靠校验器保证）。

```
用户（记录）
├─ @protocol = "记录"              ← 声明：记录（字段名唯一）
├─ 名字 = "张三"
└─ 年龄 = 30
```

**矩阵 / 张量**：数组嵌套 + `@protocol` 声明形状。

```
矩阵
├─ @protocol = "矩阵 2×2"          ← 声明形状
├─ 行1
│   ├─ 1
│   └─ 2
└─ 行2
    ├─ 3
    └─ 4
```

**正则 / 富文本**：文本 / 二进制块 + `@format`。

```
富文本
├─ 内容 = <二进制块>
└─ @format = "html"
```

**跨系统引用**：文本 + `@format = "uuid"`（外部 ID）或引用（库内节点）。

```
外部词条
├─ 值 = "550e8400-…"
└─ @format = "uuid"
```

## 四、图的表达

使用息壤的节点，同样可以用来组织各种图结构。

比如日常使用的流程图、依赖图、时序图等。

需要说明的是，图论里的「顶点」在息壤里对应的不是**一个节点**，而是**一棵子树**。

因为一个顶点通常带多种数据（名称、状态、属性等），这些数据就是一棵树。

图的「边」则使用**引用**（顶点 A 的引用 → 顶点 B 的子树根节点）来实现。

所以「图」= **多棵子树（顶点）+ 引用边（边）**。引用边可成环（E006 只禁父边环，R001 只查引用目标存在，不禁环）。

### ① 状态机（顶点带属性 + 转移成环）

```
状态：空闲                          ← 顶点（一棵子树）
├─ 说明 = "等待任务"                ← 属性
└─ 转移
    ├─ 收到任务 → 状态：处理中       ← 边（引用 → 另一顶点）
    └─ 超时 → 状态：空闲             ← 边（回边，允许）

状态：处理中                        ← 顶点
├─ 说明 = "执行中"
└─ 转移
    ├─ 完成 → 状态：空闲             ← 引用
    └─ 失败 → 状态：重试             ← 引用（环）
```

### ② 依赖图（多对多 + 共享依赖）

```
包A
├─ 版本 = "1.0"
└─ 依赖
    ├─ → 包B                        ← 引用
    └─ → 包C

包B
├─ 版本 = "2.0"
└─ 依赖
    └─ → 包C                        ← 引用（C 被 A、B 共享）
```

### ③ 流程图（循环回边）

```
开始
└─ 下一步 → 判断                   ← 引用

判断
└─ 分支
    ├─ 是 → 处理                   ← 引用
    └─ 否 → 结束                   ← 引用

处理
└─ 完成 → 判断                     ← 引用（循环回边）
```

## 五、应用场景

### 写作（事件 / 人物关系）

```
张三（人物）                          ← 根
├─ 名字 = "张三"
└─ 住所 → 北京                        ← 引用

事件-2024-001                         ← 根
├─ 主体 → 张三                        ← 引用（谁）
├─ 地点 → 北京                        ← 引用（在哪）
├─ 时间 = 1715328000
│   └─ @format = "unix timestamp"      ← 标注解析格式
└─ 前因 → 事件-2023-999               ← 引用（因果边，可环）
```

### 记忆（陈述性记忆）

和「事件」类似，多了一个「出处归因」（`@source`）：

```
事件-2024-001（记忆）               ← 根
├─ 主体 → 张三                      ← 引用
├─ 时间 = 1715328000
│   └─ @format = "unix timestamp"    ← 标注解析格式
├─ 描述 = "张三去了北京"            ← 文本
└─ @source = "file:///data/raw/dlg42.txt"   ← 出处（文件路径 / URL）
```

### 词库（词条）

```
灯                                    ← 根
├─ 词形 = "灯"
├─ 词频 = 2046
└─ 词义
    └─ 01
        ├─ 释义 = "照明或做其他用途的发光器具"
        └─ 词性
            └─ 名词
                ├─ 类属层级 = "类"
                └─ 父类 → 光源        ← 引用
```

## 六、格式转换

息壤 ↔ 其他格式（JSON / XML / YAML 无损往返；Markdown 有损、只导出）。参考实现 [tools/convert.py](https://github.com/outnever/XiRang/blob/main/tools/convert.py)。

转换时几个关键区分：

- **值是对象（嵌套）→ 子树**：JSON 的嵌套对象变成子节点（父边）。
- **跨对象引用 → 引用边**：JSON 里「指向另一对象」的引用，变成息壤的「引用」。
- **空对象 `{}` → 空类型**：空对象是「容器」，对应空类型节点（不是空文本）；空字符串 `""` 才是空文本。

### 例：JSON → 节点树

```json
{
  "光源": { "释义": "能发光的物体" },
  "灯": {
    "词形": "灯",
    "词义": { "释义": "照明器具" },
    "备注": {},
    "父类": "光源"
  }
}
```

```
光源                                ← 根
└─ 释义 = "能发光的物体"

灯                                  ← 根
├─ 词形 = "灯"
├─ 词义                              ← 子树（嵌套对象）
│   └─ 释义 = "照明器具"
├─ 备注                              ← 空类型容器（空对象 {}）
└─ 父类 → 光源                      ← 引用（跨对象）
```

### 例：节点树 → JSON（无损 vs 有损）

用前面「JSON → 节点树」中的json内容转换得到的节点树举例。

无损导出是指对于息壤节点的无损导出，而不是对于 JSON 格式的无损导出。

每个节点会保存为一个 JSON 对象，完整保留节点编号、父编号、值类型。

```json
{
  "format": "xirang", "kernel": "1.0",
  "nodes": [
    {"id": "…0000", "parent": null,   "name": "光源", "value": {"type": "text", "value": "能发光的物体"}},
    {"id": "…0001", "parent": null,   "name": "灯",   "value": {"type": "empty", "value": null}},
    {"id": "…0002", "parent": "…0001", "name": "词形", "value": {"type": "text", "value": "灯"}},
    {"id": "…0003", "parent": "…0001", "name": "词义", "value": {"type": "empty", "value": null}},
    {"id": "…0004", "parent": "…0003", "name": "释义", "value": {"type": "text", "value": "照明器具"}},
    {"id": "…0005", "parent": "…0001", "name": "备注", "value": {"type": "empty", "value": null}},
    {"id": "…0006", "parent": "…0001", "name": "父类", "value": {"type": "reference", "value": "…0000"}}
  ]
}
```

有损转换会丢失节点编号、值类型标记，引用会退化成所引用的节点名。

有损版应可以复原原有 JSON 内容，只是丢失了息壤节点的专有内容。

```json
{
  "光源": { "释义": "能发光的物体" },
  "灯": {
    "词形": "灯",
    "词义": { "释义": "照明器具" },
    "备注": {},
    "父类": "光源"
  }
}
```

## 七、二进制块与格式包装

二进制块（节点值类型 6）可以保存字节数据。

这意味着使用二进制块数据可以直接保存任何文件格式的原始字节数据。

但格式、指纹等，需要使用辅助节点表达。

比如：

- `@format`：声明格式 / 单位（全小写、用扩展名）。
- `@fingerprint`：SHA-256 摘要，内容寻址 / 校验（唯一身份）。

常用 `@format` 取值：txt md pdf docx xlsx pptx json xml csv yaml html；jpg png gif svg webp；mp3 wav flac；mp4 mov mkv；zip tar gz；py js ts c cpp java go；sqlite 等（不穷举、不强制）。

⚠️ **解码软件的安全**：按 `@format` 推荐软件打开的内容，都可能来自不可信来源。**打开 / 解码前确认来源可信；推荐软件只是「提示」，不是「必须执行」**（详见 [README 安全提醒](https://github.com/outnever/XiRang/blob/main/README.md)）。

```
头像 = [原始字节码]
├─ @format = "png"
└─ @fingerprint = "a3f5…"
```

## 八、自举与其他案例

### 息壤文档用息壤存

息壤自己的文档（README、本文件）也可以用息壤格式来表达。

可下载如下文件，通过解析程序进行分析展示其内部结构，或者直接交由语言推理大模型进行解析。

[下载 spec/息壤文档.xirang](https://github.com/outnever/XiRang/raw/main/spec/息壤文档.xirang)

内部结构应该为：

```
息壤文档                                 ← 根（空）
├─ @note = "官方文档自举存储"             ← 说明
├─ @source = "…/README.md"              ← 出处（自指）
├─ @protocol = "markdown-blocks"        ← 结构声明
├─ @history                             ← 版本历史（v1.0 + @created）
├─ README                               ← 文档（空容器）
│   ├─ @format = "markdown"
│   ├─ @source = "…/README.md"
│   ├─ @history                         ← 版本历史
│   └─ h1 / p / li / code / table …     ← Markdown 块（追加序 = 文档顺序）
├─ 模板                                  ← 文档（同构）
├─ 版本规范                               ← 文档（同构）
└─ 错误列表                               ← 文档（同构）
```

### 程序词库（带版本维度）

